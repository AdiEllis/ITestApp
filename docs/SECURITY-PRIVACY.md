# אבטחת מידע ופרטיות

המערכת מיועדת גם לקטינים. מה שממומש כאן הוא בסיס טכני בלבד. **אין לראות בו אישור לשימוש מוסדי.** לפני שימוש בבית ספר יש להשלים את הבדיקות המופיעות בסוף המסמך.

## מה ממומש

| תחום | מימוש |
|---|---|
| אימות | סיסמאות מוצפנות ב־bcrypt (cost 12). Session בצד השרת: עוגייה httpOnly עם SameSite=Lax, ו־Secure בפרודקשן. ב־DB נשמר רק hash של הטוקן. הסשן תקף 14 יום |
| נעילה והגבלת קצב | נעילה ל־15 דקות אחרי 8 כישלונות התחברות. הגבלת קצב לפי IP ולפי משתמש (נשמרת ב־Postgres, ולכן עובדת גם עם כמה שרתים). הגבלה גם על הרשמה, הצטרפות והעלאות |
| סיסמאות זמניות | חשבונות שנוצרים על ידי מורה או מנהל מחייבים החלפת סיסמה בכניסה הראשונה. אחרי החלפת סיסמה כל הסשנים האחרים מבוטלים |
| הרשאות (RBAC) | שלושה תפקידים: ADMIN, TEACHER, STUDENT. **כל** פעולת שרת עוברת דרך `src/lib/authz.ts`: מורה ניגשת רק לכיתות, מבחנים, משימות והגשות שלה. תלמיד ניגש רק למשימות שהוקצו לו ולניסיונות שלו. ה־middleware הוא רק שכבה ראשונה |
| הפרדה | כיתות שייכות לבית ספר ולמורה. תלמיד יכול להצטרף רק לכיתה בבית הספר שלו. המאגר המשותף מכיל רק עותקים של מבחנים, ללא נתוני תלמידים |
| הקלטות | נשמרות באחסון פרטי ולא ב־DB. כל גישה עוברת דרך `/api/media/[id]`, שבודק הרשאה ומפנה ל־URL חתום שתוקפו 15 דקות. רק התלמיד והמורה של הכיתה יכולים להאזין. גם מנהל המערכת אינו יכול להאזין להקלטות |
| העלאות | לפני ההעלאה נבדקים הסוג והגודל המוצהרים. אחרי ההעלאה השרת בודק שהגודל תואם וגם **את תוכן הקובץ עצמו (magic bytes)**: קובץ HTML שהתחפש ל־PDF נדחה ונמחק. מגבלות גודל לפי סוג: הקלטה 30MB, וידאו 400MB, מסמך 30MB. קבצים מוגשים עם Content-Type שנקבע בשרת, `nosniff`, ו־CSP `sandbox` (למעט PDF) |
| CSRF | ב־Server Actions הגנת Origin מובנית ב־Next.js. ב־API נבדקת כותרת Origin, ובקשה ממקור זר נדחית (נבדק ב־E2E) |
| כותרות אבטחה | CSP (מחושב בזמן ריצה), HSTS בפרודקשן, `X-Frame-Options`, `Referrer-Policy`, ו־`Permissions-Policy` (מיקרופון בלבד) |
| שגיאות | למשתמש מוחזרות הודעות כלליות בלבד. פרטים טכניים נרשמים רק בלוג השרת. משאב שאין אליו הרשאה מחזיר 404, כדי לא לחשוף שהוא קיים |
| יומן פעולות | נרשמים: התחברות, יצירה ומחיקה של תלמידים, איפוס סיסמה, התחלה והגשה של מבחן, פרסום ציון, שיתוף והסרה מהמאגר, מחיקות, פעולות מנהל ומשימת השמירה. המנהל יכול לצפות ביומן ב־`/admin/audit` |
| מחיקה | מורה יכולה למחוק תלמיד יחד עם כל ההקלטות שלו מהאחסון, אלא אם התלמיד רשום גם אצל מורה אחרת, ואז רק מנהל יכול. מחיקת משימה מוחקת את ההקלטות שלה. מנהל יכול למחוק כל משתמש |
| מדיניות שמירה | לכל בית ספר מוגדר מספר ימים לשמירת הקלטות, וברירת המחדל נקבעת ב־`DEFAULT_RECORDING_RETENTION_DAYS`. `npm run retention` מוחק הקלטות ישנות, העלאות נטושות וסשנים שפג תוקפם. **יש להריץ אותו פעם ביום** |
| מזעור מידע | לתלמידים אין צורך בדוא״ל. שם המשתמש נוצר אוטומטית. אין שימוש ב־analytics, בפרסומות או בשירותי צד שלישי (מלבד אחסון ו־DB) |

## לפני שימוש אמיתי בבית ספר: נדרש ממך או מבית הספר

- [ ] ייעוץ משפטי לגבי **חוק הגנת הפרטיות** (כולל תיקון 13, בתוקף מאוגוסט 2025) ו**תקנות אבטחת מידע (2017)**: מהי רמת האבטחה של המאגר, האם נדרש מינוי ממונה, ונהלים.
- [ ] בדיקת **חוזרי מנכ״ל והנחיות משרד החינוך** לשימוש בכלים מקוונים ובשירותי ענן עם מידע על תלמידים. ייתכן שנדרש אישור (למשל במסגרת גפ״ן או אבטחת מידע של המשרד).
- [ ] **הסכמת הורים ויידוע:** הקלטות קול של קטינים. יש לנסח מכתב או טופס הסכמה.
- [ ] **מיקום שמירת המידע:** לבחור אזור (region) לאחסון ול־DB ולוודא שהוא עומד בדרישות.
- [ ] **מדיניות פרטיות ותנאי שימוש:** הקיימים ב־`/privacy` הם טיוטה.
- [ ] **בדיקת חדירות (penetration test)** חיצונית.
- [ ] הגדרת **גיבויים** ל־DB ולאחסון, ובדיקה ששחזור עובד.
- [ ] מנגנון "שכחתי סיסמה" באמצעות דוא״ל למורים (כרגע איפוס מתבצע דרך מנהל).
